# RetalCare

لرفع المشروع على GitHub وربطه بـGoogle Cloud Run، اتبع [دليل النشر](DEPLOYMENT.md). ملف `Dockerfile` في الجذر يبني الموقع ويقدمه مع السيرفر من خدمة واحدة. إعداد قاعدة البيانات في `server/.env` محلياً أو Secret Manager على Cloud Run. لا تفتح الخدمة للعامة قبل معالجة ملاحظات حماية الـAPI في الدليل.

المشروع مقسّم إلى ثلاثة أجزاء مستقلة:

```text
patient-billing/
├── server/      السيرفر وقواعد الاتصال بالبيانات
├── app/         تطبيق Expo القديم
│   └── archive/ ملفات الاسترجاع والمراجع القديمة
└── website/     موقع React + Vite واختباراته
```

## التشغيل من المجلد الرئيسي

- `npm run server` لتشغيل السيرفر على المنفذ 5000.
- `npm run website` لتشغيل الموقع (في نافذة أوامر أخرى).
- `npm run build` لبناء الموقع داخل `website/dist`.
- `npm test` لتشغيل اختبارات الموقع.
- `npm run app` لتشغيل تطبيق Expo القديم بعد تثبيت مكتباته.

لكل جزء ملف `package.json` مستقل. عند إعداد جهاز جديد، ثبّت المكتبات باستخدام `npm --prefix server install` و`npm --prefix website install`. التطبيق القديم يحتاج `npm --prefix app install` فقط إذا أردت تشغيله؛ محتواه محفوظ كما كان، ولا يُستخدم في بناء الموقع.

الموقع يمرّر طلبات `/api` إلى السيرفر المحلي على المنفذ 5000. إعدادات تغيير العنوان موجودة في `website/.env.example`، والتفاصيل في `website/README.md`.

تم نسخ السيرفر من `D:\retal-backend` مع ترك الأصل للاحتياط. استخدم نسخة `server` داخل هذا المشروع للتعديلات التالية، ولا تشغّل النسختين على المنفذ نفسه. لم تُنقل أو تُحذف قاعدة البيانات.
